📦 1. Le principe des boîtes

Chaque fonction ou bloc d'accolades { ... } forme une boîte fermée. Les variables créées dedans y restent protégées.

👀 2. Sens unique de vision

De l'intérieur, on voit vers l'extérieur. Mais de l'extérieur, il est impossible de voir ce qui est caché à l'intérieur !

🧱 3. const / let vs var

const et let restent sagement enfermés dans leur bloc {}. var s'échappe des blocs et n'est bloqué que par les fonctions.

Code 1 Accès vers l'extérieur (Portée globale / parente)
Affiche : Chez John Doe
const restaurant = "Chez John Doe"; function afficher() { console.log(restaurant); } afficher();

La variable restaurant n'est pas dans la fonction. La fonction regarde donc dehors dans le bloc parent et la trouve sans problème.

⭐ Règle : Une fonction peut toujours lire les variables déclarées à l'extérieur d'elle-même.
Code 2 Variable enfermée dans une fonction (Portée locale)
Erreur : total is not defined
function calculer() { const total = 3500; return total; } calculer(); console.log(total); // ❌ Crash !

La variable total est née à l'intérieur de calculer(). Dès que la fonction finit, la variable disparaît. On ne peut pas y toucher depuis l'extérieur.

⭐ Règle : Les variables d'une fonction sont invisibles et inaccessibles depuis l'extérieur.

Codes 3 à 5
Code 3 Portée lexicale : fidélité au lieu de naissance
Affiche : Abidjan
const ville = "Abidjan"; function afficherVille() { console.log(ville); } function livrer() { const ville = "Bouaké"; afficherVille(); } livrer();

afficherVille a été écrite là où ville = "Abidjan". Même appelée depuis livrer(), elle regarde là où elle a été créée, pas là où elle est appelée.

⭐ Règle : Une fonction garde toujours le lien avec l'endroit où elle a été codée.
Code 4 Portée de bloc : le if crée une barrière
Erreur : message is not defined
const total = 4000; if (total > 3000) { const message = "Livraison offerte"; } console.log(message); // ❌ Crash !

const et let s'arrêtent à l'accolade }. La variable message a été créée dans le bloc if, elle est détruite dès qu'on en sort.

⭐ Règle : Les accolades { } d'une condition ou d'une boucle emprisonnent let et const.
Code 5 Masquage de variable (Shadowing)
Affiche : Bissap puis Garba
let boisson = "Garba"; function commander() { let boisson = "Bissap"; console.log(boisson); // Bissap } commander(); console.log(boisson); // Garba

La fonction redéfinit un let boisson à elle. Elle utilise sa propre valeur locale ("Bissap") sans écraser la variable de départ qui reste intacte ("Garba").

⭐ Règle : Une variable locale masque l'externe sans la modifier.

Séance 1 (Atelier 1) : Déclaration, imbrication et boucles asynchrones

Codes 6 à 8
Code 6 Zone de Mort Temporaire : utiliser avant de déclarer
Erreur : Cannot access before init
console.log(quantite); // ❌ Crash immédiat ! let quantite = 2;

Avec let et const, il est interdit de lire une variable avant la ligne où elle est écrite. JavaScript bloque l'accès tant que l'initialisation n'est pas passée.

⭐ Règle : Toujours déclarer ses variables tout en haut avant de s'en servir.
Code 7 Fonctions imbriquées (Poupées russes)
Affiche : 10
function exterieure(n) { function interieure() { return n * 2; } return interieure(); } console.log(exterieure(5));

La fonction interieure est à l'intérieur de exterieure. Elle a donc un accès direct au paramètre n (5). Elle fait $5 \times 2 = 10$.

⭐ Règle : Une fonction interne hérite de toutes les variables de sa fonction mère.
Code 8 var vs let dans une boucle avec retard (setTimeout)
var: 4, 4, 4 | let: 1, 2, 3
for (var i = 1; i <= 3; i++) { setTimeout(() => console.log("var :", i), 100); } for (let j = 1; j <= 3; j++) { setTimeout(() => console.log("let :", j), 200); }

var partage une seule case mémoire qui finit à 4. let fabrique une case neuve à chaque tour, donc chaque timer garde sa propre valeur.

⭐ Règle : Toujours utiliser let dans une boucle, jamais var.

💡 Résumé en 3 lois universelles :

  1. La vision va du dedans vers le dehors : On peut piocher chez les parents, jamais chez les enfants.
  2. Lieu de naissance, pas lieu d'appel : Une fonction se souvient toujours de l'endroit où le développeur l'a écrite.
  3. Adoptez const et let : Oubliez var, qui fuit hors des blocs et crée des bugs dans les boucles.
